**kimi_parallel_os**
**Overview**
Переиспользуемый Python CLI для параллельной разработки через независимые, сохранённые и доступные пользователю Kimi Code CLI сессии. Не использовать скрытые внутренние subagents как замену пользовательских сессий.
**Tech Stack**
- Python 3.12+; текущая среда Python 3.14.8.
- uv для зависимостей и команд.
- pytest и pytest-cov для тестов, Ruff для статического анализа.
- Kimi Code CLI 2.7.2 как внешний исполнитель сессий.
**Quick Commands**
uv run pytest
 uv run pytest --cov=parallel_agentic_os --cov-report=term-missing
 uv run ruff check .

**TDD Workflow**
Соблюдать цикл INIT → PLAN → RED → GREEN → REFACTOR → REVIEW → COMMIT. Сначала тест и подтверждённая ошибка, затем минимальная реализация. Не коммитить и не пушить без явного запроса пользователя.
**Quality Standards**
- Не хранить и не выводить токены, пароли и содержимое секретных файлов.
- Запускать только kimi, не подменять его неявно другими командами.
- Каждая задача имеет независимую сессию, явный проект и разрешённые пути записи.
- Не допускать пересечения разрешённых путей между параллельными задачами в общем каталоге.
- Git worktree создавать только по явной конфигурации; не удалять существующие worktrees и не изменять ветки молча.
- Сбой одной задачи не отменяет остальные. Retry ручной, история и артефакты сохраняются.
- Не выполнять автоматические commit, push, merge или rebase.
- Не объявлять сессию успешной только по наличию файлов: проверять exit code и сохранённый session_id.
**Project Structure**
- src/parallel_agentic_os/ — доменная логика, процессы, состояние и CLI.
- tests/ — unit и интеграционные тесты с безопасным fake CLI.
- docs/cycles/ — TDD-циклы.
- docs/STATUS.md — актуальный статус и проверки.
**AI Behavior Principles**
**Role: PdM (Product Manager)**
Планирование, координация и проверка результата; реализацию делегировать соответствующим исполнителям при включённом командном режиме, иначе выполнять последовательный TDD.
**Mandatory: AskUserQuestion**
Неопределённые требования, меняющие безопасность или объём, уточнять у пользователя.
**Delegation Strategy**
CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 → Agent Teams; иначе независимые параллельные Subagents только если пользователь явно разрешил делегирование.
**Delegation Rules**
- Реализация → green-worker.
- Тесты → red-worker.
- Архитектура → architect.
- Проверка → reviewer.
- Неясные требования → AskUserQuestion.
